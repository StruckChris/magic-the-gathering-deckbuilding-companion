# Competitive List Library

This is a navigation and provenance index. Each [archetype primer](../archetypes/archetype-library.md) owns its historical explanation, selected package, direct external source links, Commander translation, and sustainable-advantage lesson. Retrieve that primer rather than treating this table as a complete explanation.

The 22 primary references below are distinct lists. A source article can publish more than one list, so distinct lists need not have distinct source domains or URLs. Secondary references deliberately connect related families. Their use does not make archetypes mutually exclusive.

## How to Use a Reference

Start with the user's idea and available cards. Name the historical list, explain how its shell created advantage, how the engine sustained and converted it, and what finished the game. Then return to the supplied pool: which functions can be reproduced, which change in multiplayer, and which are missing?

The 2000s-era method is the focus. Earlier roots and later teaching articles explain its continuity. A publication year is not automatically an event year, and a test or teaching list is not a tournament result. Functional parallels are instructional interpretations, not proof of direct historical descent.

A selected package is not a full list, current legality claim, inventory record, or purchase recommendation. Follow the primer's external source before answering exact-count or full-deck questions. Sources were inspected on 1 October 2026.

## Adding an Archetype

The library is a starting set, not a limit on the player's ideas. When the player requests another archetype, seek a specific primary-source list: official event coverage, an organizer's published list, a firsthand designer or pilot report, or a preserved official decklist. When competitive evidence would distort the strategy, use an appropriately labeled Commander or other direct example. If reliable evidence is unavailable, explain that limitation rather than inventing a competitive lineage.

If the player also asks to save the addition, place the direct source link, selected package, historical context, sustainable-advantage explanation, and overlaps in an archetype primer, then add its index entry here and in the archetype library. Verify counts before reproducing a package and distinguish results from proposals. Avoid duplicate historical explanations or several primers with the same primary example merely to fill coverage.

Explain how the method could work with the player's supplied cards. Adding a reference does not establish ownership, authorize outside-card recommendations, or change a decklist.

Current metagame questions still require current evidence. Rules verification and access policies live in the [rules guide](../guides/rules-and-competitive-context.md) and [lookup guide](../guides/card-lookup-and-access.md).
